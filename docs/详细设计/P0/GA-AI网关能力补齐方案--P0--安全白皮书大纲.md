## 1. 目的与使用说明

### 1.1 目的

- 在 P0 阶段**锁定白皮书结构与口径**，避免 P1 边写边改、口径漂移；
- 为 P1 M4-M5 的**分工（谁写哪章）与排期**提供依据；
- 确保对外发布内容**与威胁模型、侧信道披露、合规材料三者口径一致**；
- 提前暴露"素材缺口"，驱动 P1 的 GAP 闭环（对应威胁模型 §10.2）。

### 1.2 使用方式

| 产品经理 | 统筹分工（**谁写哪章**，与 §5 角色列闭环）、对外口径与承诺清单 |

## 3. 编写规范与口径约束

### 3.1 事实来源优先级

```
① 代码实测（`文件:符号`，**不用行号**） ＞ ② 威胁模型本体 ＞ ③ 主方案/详设 ＞ ④ 标准/行业经验
```
任何安全能力声明**必须可回溯到 ①②③**；不得引用"行业普遍做法"代替本项目事实。

### 3.2 措辞红线（**以《侧信道风险披露说明》§7 为准**）

> 本节为**摘要**；完整清单以披露说明 §7 为唯一口径（**禁止 7 条 + 应避免 5 条 + 强制限定词 4 条**）。

**禁止（节选，逐字见披露说明 §7.1）**

| 禁止 | 应改为 |
|---|---|
| 绝对安全 / 不可攻破 / 100% 保密 | 提供增强保护 / 显著降低风险 |
| 防侧信道攻击 / 完全防护侧信道 | 缓解侧信道风险 / 降低侧信道可利用性 |
| 宿主完全无法访问 / 完全隔离 | 宿主无法直接读取飞地内存（TDX 正常工作前提下） |
| 已通过密评 / 已获等保三级 | 密评路径规划中 / 已完成差距分析（视阶段） |
| 已实现完整远程证明 | 已实现飞地证明机制；完整硬件证明链在 P1 接入 |

**应避免（披露说明 §7.2）**：军事级/银行级加密、零信任、单用"硬件级安全"、"免疫 Spectre"、"密态=全程不可见"。

**强制限定词（披露说明 §7.3）**：凡宣称 TEE 安全能力，须同时含"**增强**保护（非绝对安全）""**降低**风险（非消除/防护）""在 TDX 正常工作前提下"，且"**已实现**"与"**规划中**"须分开表述。

### 3.3 版本与发布控制

- 白皮书正文版本独立于本文档：正文 `v1.0`（P1 M5）；
- **正文须显式声明所依据的《TEE 威胁模型》与《侧信道风险披露说明》版本**（防与本体脱节）；
- 每次发布须经 §7 门禁（安全 + 产品 + 法务三方签署）；
- 变更须记录在正文附录"变更记录"，并同步复核与三份 P0 文档的一致性。

### 3.4 图表与脱敏

- 架构图不得暴露内网 IP/域名/真实密钥/真实租户数据；
- 所有示例须为**构造示例**，禁止使用真实客户数据（个人信息保护法）；
- 个人信息处理口径对齐威胁模型 §3.4 的 **PIPL 条款映射**（第 13/17/19/38-43/47 条）。
