### 3.3 U-7 单副本可用性：快照恢复 SOP 与演练（B 类）

单副本是 C-18 的既定权衡（SQLite 多写者＋进程内限流），不迁移共享存储无法根除。本轮交付**可执行的恢复 SOP**，把故障恢复时间压到 RTO≤30min。

**备份规范（每日，运维落地）**：

- 对 `tenant.db` 与 `billing.db` 使用 SQLite 在线备份（`VACUUM INTO '<快照>'` 或 backup API），保证含 WAL 的一致性视图；两 store **同时点**快照；
- 快照文件 0700、加密存储，保留 30 天；每次备份记录 sha256 与库内行计数/审计锚点；
- 备份任务失败立即告警（不得静默跳过）。

**恢复 SOP**：

1. 门户宣告维护并摘流量（入口返回维护页）；
2. 确认无进程写库（停进程或 scale=0），避免恢复后被旧 WAL 覆盖；
3. 取最近健康快照还原 `TENANT_STORE_PATH` 与 billing 路径；**删除残留 `-wal/-shm`**，使状态以快照为准；
4. 完整性校验：`PRAGMA integrity_check;` 返回 `ok`；核对行计数与审计锚点；
5. 启动进程，`/readyz` 返回 ready；冒烟（登录、查用量、查订阅）；
6. 恢复流量并公告。

**RTO≤30min 演练清单（灰度前必须演练并留记录）**：

| # | 动作 | 预算（分钟） | 实际 | 负责人 |
|---|---|---|---|---|
| 1 | 宣告维护、摘流量 | 0-3 | | 运维 |
| 2 | 定位最近健康快照、校验 sha256 | 3-8 | | 运维 |
| 3 | 还原双 store、清 WAL、integrity_check | 8-15 | | 运维 |
| 4 | 启动进程、readyz、冒烟三项 | 15-22 | | 后端＋运维 |
| 5 | 恢复流量、公告 | 22-28 | | 运维 |
| 6 | 演练记录归档、差距回填 | 28-30 | | 运维 |

通过判据：全流程 ≤30 分钟且数据校验一致；未通过则优化 SOP 并重新演练。

### 3.4 U-6 邮件令牌 pepper 轮转设计（B 类，维持 P2）

- 现状：`TENANT_TOKEN_PEPPER` 为单一全局值，token_hash = SHA-256(pepper‖token)；
- P2 设计：hash 带版本前缀 `v<n>:<sha256(pepper_n‖token)>`；配置支持多版本（`v1:..,v2:..`），以最新版本签发、按前缀选择 pepper 校验，旧令牌自然过期（注册 24h/重置 1h，窗口短，轮转冲击小）；
- 结论：轮转收益低、且 v1.3 已主动定 P2，本轮**不实现**（遵循极简优先、不做需求外功能）；纳入 P2 待办。
